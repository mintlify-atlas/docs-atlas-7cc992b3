`ItemServico` is the associative entity that links a `Servico` from the workshop's service catalog to a `OrdemServico`. Each record captures how many hours were worked (`tempo_hora`), the hourly rate that was applied at the time the item was created (`valor_hora`), and whether the client approved this specific line item. A single service order can have multiple `ItemServico` records — one for each distinct service performed during the visit.

## Fields

<ResponseField name="id" type="integer">
  Auto-generated primary key. Assigned by the database on creation.
</ResponseField>

<ResponseField name="tempo_hora" type="integer">
  The number of hours worked on this service. Must be **greater than 0**. Defaults to `1`. Multiplied by `valor_hora` to determine this item's labour contribution to the order total.
</ResponseField>

<ResponseField name="valor_hora" type="float">
  The hourly rate applied for this service, in Brazilian Reais (BRL). Must be **≥ 0**. Defaults to `0.0`. This value is **frozen at creation time** — it reflects the `Servico.preco` value at the moment the item was added to the order and will not be affected by future catalog price changes.
</ResponseField>

<ResponseField name="aprovado" type="boolean">
  Whether the client approved this specific service line item. Defaults to `true`. Items with `aprovado = false` are excluded from the order's `valor_total` calculation and from payment eligibility.
</ResponseField>

<ResponseField name="servico_id" type="integer" required>
  Foreign key referencing the `Servico` catalog entry that this line item is based on.
</ResponseField>

<ResponseField name="ordem_servico_id" type="integer" required>
  Foreign key referencing the `OrdemServico` that this line item belongs to.
</ResponseField>

<ResponseField name="created_at" type="datetime">
  ISO 8601 timestamp of when the record was created. Set automatically by the server in UTC.
</ResponseField>

<ResponseField name="updated_at" type="datetime">
  ISO 8601 timestamp of the last update. Refreshed automatically on every write operation in UTC.
</ResponseField>

## Price Invariance

When an `ItemServico` is created, the system copies the current `Servico.preco` value into `valor_hora`. From that moment on, `valor_hora` is **immutable with respect to catalog changes**: if the catalog price for that service is later updated (e.g., the workshop raises its rates), existing `ItemServico` records retain the price that was in effect when the item was first added. This ensures consistent invoicing across the full lifespan of a service order.

```
labour_contribution = tempo_hora × valor_hora   (only if aprovado = true)
```

## Approval Workflow

Client approval is tracked at the individual line-item level via the `aprovado` boolean. This supports partial approval scenarios where a client agrees to some services but declines others during the budgeting phase.

<Note>
  When a client approves only a subset of service items, only the approved items are summed into `OrdemServico.valor_total`. For example, if an order has three services — alignment (approved), shock absorber replacement (approved), and a full engine scan (declined) — the order total will only include alignment and shock absorber labour. The declined item remains on the order as a record of what was proposed and refused.
</Note>

## Locked Orders

Service orders with a status of `concluida` (completed) or `cancelada` (cancelled) are immutable. Attempting to add, modify, or remove an `ItemServico` on a locked order raises a `RegraDeNegocioException`:

```json
{
  "status_code": 422,
  "detail": "Regra de negócio violada"
}
```

## Example

The following record is taken from seed order #1 (routine oil change on a 2022 Chevrolet Onix). Note that `aprovado` is `false` — this item was logged as part of the initial budget but the client had not yet confirmed it at the time the seed snapshot was taken:

```json
{
  "id": 1,
  "tempo_hora": 1,
  "valor_hora": 85.0,
  "aprovado": false,
  "servico_id": 1,
  "ordem_servico_id": 1,
  "created_at": "2025-01-01T10:00:00Z",
  "updated_at": "2025-01-01T10:00:00Z"
}
```

Here is an approved item from order #3 (electronic injection fault), where both the scanner diagnosis and injector cleaning were confirmed by the client:

```json
{
  "id": 4,
  "tempo_hora": 1,
  "valor_hora": 210.0,
  "aprovado": true,
  "servico_id": 9,
  "ordem_servico_id": 3,
  "created_at": "2025-01-05T09:00:00Z",
  "updated_at": "2025-01-05T09:00:00Z"
}
```
