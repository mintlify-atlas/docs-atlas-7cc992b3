Every `GET /` list endpoint in the Oficina Mecânica API returns results wrapped in a **pagination envelope** rather than a raw array. This design keeps response sizes predictable, prevents unbounded queries on large tables, and gives clients all the metadata they need to build navigation controls without issuing a separate count request. Pagination is handled through the shared `Paginacao` model defined in `app/models/paginacao.py`. Most list endpoints share the `pagina` and `tamanho_pagina` parameter names; the veiculos endpoint uses the abbreviated `p` and `tp` instead — a deliberate difference that must be accounted for when building clients.

---

## Pagination Parameters

Most list endpoints accept `pagina` and `tamanho_pagina` to control which page of results is returned. The `GET /veiculos/` endpoint is the exception: it uses `p` and `tp` for the same purpose. Both sets of parameters follow the same semantics.

### Standard parameters (`/clientes/`, `/mecanicos/`, `/servicos/`, `/pecas/`)

<ParamField query="pagina" type="int" default="1">
  The page number to return. Must be **≥ 1**. Requesting a page beyond the last available page returns an empty `dados` array with accurate totals in the `paginacao` envelope.
</ParamField>

<ParamField query="tamanho_pagina" type="int" default="10">
  The maximum number of records to include in a single page. Accepted range is **1 – 100**.
</ParamField>

### Abbreviated parameters (`/veiculos/` only)

<Warning>
  The `GET /veiculos/` endpoint uses `p` and `tp` instead of `pagina` and `tamanho_pagina`. Sending `pagina` or `tamanho_pagina` to this endpoint will have no effect — the parameters will be silently ignored and the defaults will apply.
</Warning>

<ParamField query="p" type="int" default="1">
  Page number for the veiculos list endpoint. Must be **≥ 1**. Equivalent to `pagina` on all other endpoints.
</ParamField>

<ParamField query="tp" type="int" default="10">
  Page size for the veiculos list endpoint. Accepted range is **1 – 100**. Equivalent to `tamanho_pagina` on all other endpoints.
</ParamField>

Results within each page are ordered by the primary searchable field of the resource (`nome` for clientes and mecânicos, `placa` for veículos, `descricao` for serviços, `nome` for peças). This ordering is applied server-side and is not configurable via query parameters.

## Response Envelope

Every list response follows the same two-key structure. The `dados` array contains the actual records for the requested page, and the `paginacao` object contains all the metadata needed to navigate pages.

```json
{
  "dados": [
    {
      "id": 1,
      "nome": "Carlos Andrade",
      "telefone": "11999998888",
      "email": "carlos@example.com",
      "created_at": "2024-03-15T10:30:00Z",
      "updated_at": "2024-03-15T10:30:00Z"
    }
  ],
  "paginacao": {
    "total_registros": 42,
    "total_paginas": 5,
    "pagina_atual": 1,
    "tamanho_pagina": 10
  }
}
```

### Envelope Fields

| Field | Type | Description |
|---|---|---|
| `dados` | `array` | The records for the current page. Empty array `[]` when the page exceeds the total or no records match the applied filters. |
| `paginacao.total_registros` | `int` | Total number of records that match the active filters, across **all** pages. |
| `paginacao.total_paginas` | `int` | Total number of pages given the current page size. Calculated server-side as `ceil(total_registros / tamanho_pagina)`. Returns `0` when there are no matching records. |
| `paginacao.pagina_atual` | `int` | The page number that was returned. Echoes back the page parameter that was sent. |
| `paginacao.tamanho_pagina` | `int` | The page size that was applied. Echoes back the page-size parameter that was sent. |

## Per-Resource Filters

In addition to pagination parameters, each list endpoint accepts its own set of optional filter query parameters. All filters are **additive** — multiple filters applied together narrow the result set further (logical AND). Omitting a filter parameter means that field is not constrained.

| Resource | Pagination params | Filter parameter | Match type | Description |
|---|---|---|---|---|
| `GET /clientes/` | `pagina`, `tamanho_pagina` | `nome` | Partial, case-insensitive | Filter clients whose name contains the given string |
| `GET /clientes/` | `pagina`, `tamanho_pagina` | `email` | Partial, case-insensitive | Filter clients whose email contains the given string |
| `GET /mecanicos/` | `pagina`, `tamanho_pagina` | `nome` | Partial, case-insensitive | Filter mechanics whose name contains the given string |
| `GET /mecanicos/` | `pagina`, `tamanho_pagina` | `especialidade` | Exact | Filter mechanics by declared speciality (`EspecialidadeMecanico` enum value) |
| `GET /veiculos/` | **`p`, `tp`** | `placa` | Partial, case-insensitive | Filter vehicles whose licence plate contains the given string |
| `GET /veiculos/` | **`p`, `tp`** | `cliente_id` | Exact | Filter vehicles that belong to the specified client ID |
| `GET /servicos/` | `pagina`, `tamanho_pagina` | `descricao` | Partial, case-insensitive | Filter catalogue services whose description contains the given string |
| `GET /pecas/` | `pagina`, `tamanho_pagina` | `nome` | Partial, case-insensitive | Filter catalogue parts whose name contains the given string |

<Note>
  All string-based filters use a **case-insensitive partial match** implemented as a SQL `ILIKE '%value%'` clause. Searching for `carlos` will match `Carlos Andrade`, `carlos.silva`, and any record containing that substring regardless of capitalisation.
</Note>

## Examples

### List clients — paginated

Fetch the second page of clients, five records per page:

```bash
curl "http://localhost:8000/clientes/?pagina=2&tamanho_pagina=5"
```

### List clients — paginated with name filter

Fetch clients whose name contains `Carlos`, five per page:

```bash
curl "http://localhost:8000/clientes/?pagina=2&tamanho_pagina=5&nome=Carlos"
```

### List mechanics — filter by speciality

Fetch all mechanics specialising in `suspensao_freios`:

```bash
curl "http://localhost:8000/mecanicos/?especialidade=suspensao_freios"
```

### List vehicles — paginated (note `p` and `tp`)

Fetch the second page of vehicles, five records per page. Use `p` and `tp` — **not** `pagina` and `tamanho_pagina`:

```bash
curl "http://localhost:8000/veiculos/?p=2&tp=5"
```

### List vehicles — filter by owner (note `p` and `tp`)

Fetch all vehicles belonging to client with ID `7`:

```bash
curl "http://localhost:8000/veiculos/?cliente_id=7&p=1&tp=10"
```

### List catalogue parts — partial name search

Search for parts whose name contains `filtro`:

```bash
curl "http://localhost:8000/pecas/?nome=filtro&tamanho_pagina=20"
```

---

## Notes on Edge Cases

- When **no records match** the applied filters, the response returns HTTP **200** with `dados: []` and `paginacao.total_registros: 0`, `paginacao.total_paginas: 0`.
- Requesting a page value **greater than `total_paginas`** returns HTTP **200** with an empty `dados` array. This avoids errors in pagination controls that race with concurrent deletes.
- The pagination parameters are **always echoed back** in the `paginacao` envelope, so clients do not need to track what they sent to interpret the response.
